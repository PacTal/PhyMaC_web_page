# Decap CMS Integration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrar Decap CMS al sitio estático de PhyMaC para que editores no técnicos puedan publicar artículos de blog desde `/admin` sin tocar código, usando archivos Markdown como fuente de verdad.

**Architecture:** Estrategia A del spec — agregar un build script Node.js (`scripts/build-blog.js`) que lee archivos `.md` de `content/blog/`, convierte Markdown a HTML con `marked`, y regenera `blog-data.js` en el formato `const BLOG_POSTS = [...]` que ya consume `blog.js`. El panel de administración son dos archivos estáticos (`admin/index.html` + `admin/config.yml`) que Decap CMS carga en el browser. La autenticación es Netlify Identity (configuración manual en dashboard — fuera del scope de este plan).

**Tech Stack:** Node.js (build script), `gray-matter` (frontmatter parsing), `marked` (Markdown→HTML), `jest` (tests), Decap CMS 3.x (CDN), Netlify Identity (OAuth GitHub).

- [ ] **Step 4: Crear `scripts/build-blog.js` con la función `parsePost`**

```js
// scripts/build-blog.js
const fs = require('fs');
const path = require('path');
const matter = require('gray-matter');
const { marked } = require('marked');

/**
 * Lee un archivo .md y retorna un objeto compatible con BLOG_POSTS.
 * @param {string} filePath - Ruta absoluta al archivo .md
 * @param {number} id - ID numérico a asignar al post
 * @returns {Object} Post compatible con el formato BLOG_POSTS
 */
function parsePost(filePath, id) {
  const raw = fs.readFileSync(filePath, 'utf-8');
  const { data, content } = matter(raw);

  // La fecha puede ser un objeto Date (gray-matter la parsea) o string
  const dateStr = data.date instanceof Date
    ? data.date.toISOString().split('T')[0]
    : String(data.date);

  return {
    id,
    title: data.title || '',
    slug: data.slug || path.basename(filePath, '.md'),
    date: dateStr,
    author: data.author || '',
    category: data.category || '',
    image: data.image || '',
    summary: data.summary || '',
    content: marked(content).trim(),
    pdf_url: data.pdf_url || null
  };
}

module.exports = { parsePost };
```

```js
// scripts/build-blog.js
// Lee archivos .md de content/blog/ y genera blog-data.js

const fs = require('fs');
const path = require('path');
const matter = require('gray-matter');
const { marked } = require('marked');

const BLOG_DIR = path.join(__dirname, '../content/blog');
const OUTPUT_FILE = path.join(__dirname, '../blog-data.js');

/**
 * Lee un archivo .md y retorna un objeto compatible con BLOG_POSTS.
 * @param {string} filePath - Ruta absoluta al archivo .md
 * @param {number} id - ID numérico a asignar al post
 */
function parsePost(filePath, id) {
  const raw = fs.readFileSync(filePath, 'utf-8');
  const { data, content } = matter(raw);

  const dateStr = data.date instanceof Date
    ? data.date.toISOString().split('T')[0]
    : String(data.date);

  return {
    id,
    title: data.title || '',
    slug: data.slug || path.basename(filePath, '.md'),
    date: dateStr,
    author: data.author || '',
    category: data.category || '',
    image: data.image || '',
    summary: data.summary || '',
    content: marked(content).trim(),
    pdf_url: data.pdf_url || null
  };
}

/**
 * Lee todos los archivos .md de un directorio y retorna un array de posts.
 * @param {string} dir - Ruta absoluta al directorio con los .md
 * @returns {Object[]} Array de posts
 */
function generateBlogData(dir) {
  const files = fs.readdirSync(dir)
    .filter(f => f.endsWith('.md'))
    .sort(); // orden alfabético = cronológico (filenames con fecha YYYY-MM-DD)

  return files.map((file, index) =>
    parsePost(path.join(dir, file), index + 1)
  );
}

/**
 * Genera el string del archivo blog-data.js a partir del array de posts.
 * @param {Object[]} posts
 * @returns {string}
 */
function generateBlogDataSource(posts) {
  return `/**
 * AUTO-GENERATED — No editar manualmente.
 * Generado por: npm run build:blog
 * Fuente: content/blog/*.md
 */

const BLOG_POSTS = ${JSON.stringify(posts, null, 2)};

// Compatibilidad CommonJS para tests y scripts
if (typeof module !== 'undefined' && module.exports) {
  module.exports = BLOG_POSTS;
}
`;
}

// Punto de entrada — solo corre cuando se ejecuta directamente
if (require.main === module) {
  const posts = generateBlogData(BLOG_DIR);
  fs.writeFileSync(OUTPUT_FILE, generateBlogDataSource(posts));
  console.log(`✓ blog-data.js generado con ${posts.length} artículos`);
}

module.exports = { parsePost, generateBlogData, generateBlogDataSource };
```

```js
// scripts/drive-utils.js
/**
 * Transforma un link de Google Drive de visor a descarga directa de PDF.
 * @param {string|null|undefined} url - URL de Drive con /view
 * @returns {string|null}
 */
function driveToDownload(url) {
  if (!url) return null;
  if (url.includes('/export')) return url;
  return url.replace(/\/view.*$/, '/export?format=pdf');
}

module.exports = { driveToDownload };
```

```markdown
En PhyMaC explicamos la ciencia más allá de un tablero; la descubrimos construyendo. Recientemente, aceptamos un nuevo desafío: llevar nuestro laboratorio a la fundación CreSiendo en la vereda El Rosal, donde disfrutamos del ingenio de niños y jóvenes que movieron un objeto aprovechando el aire.

## El reto: cohetes propulsados por aire (Newton en la vida real)

Para entender la tercera ley de Newton (acción y reacción), hay que verla funcionar. La actividad principal consistió en la construcción de un artefacto sencillo pero poderoso: un cohete impulsado por aire.

Los participantes, con edades entre los ocho y quince años, tuvieron que manipular materiales como cintas, palillos y globos. Durante la actividad reflexionaron sobre:

- ¿Qué voy a hacer?
- ¿Qué necesito?
- ¿Cómo aplico lo aprendido?

Este enfoque hace parte de nuestro ciclo STEM de tres fases, diseñado para promover un aprendizaje práctico donde la experimentación es el centro del proceso.

## Ingenio colaborativo: "makers" apoyando a "makers"

La jornada presentó desafíos reales. Para los niños más pequeños (8-10 años), la manipulación de los materiales y la lógica del cohete resultaron ser un reto exigente. Sin embargo, aquí es donde brilla el aprendizaje colaborativo.

Dos jóvenes de quince años asumieron el rol de monitores, guiando a sus pares más pequeños y ayudándoles a resolver problemas técnicos sobre la marcha. Gracias a este apoyo y al acompañamiento de nuestro equipo facilitador, todos lograron involucrarse y ver sus prototipos en acción.

## Resultados y proyección

Más allá de la diversión, buscábamos que los niños reconocieran la física detrás del juego: la relación entre la dirección del aire expulsado y el movimiento del cohete. Se observó una comprensión inicial del fenómeno, validando que la construcción de artefactos es una estrategia efectiva para aprender ciencia.

Para continuar el aprendizaje, dejamos planteado el reto llamado **El cohete dirigido**. En casa los niños diseñarán un nuevo cohete, lo dibujarán y explicarán porque llegará más alto.

## Agradecimientos

Agradecemos a la Fundación CreSiendo por abrirnos sus puertas y confiar en propuestas educativas que fomentan el aprendizaje activo. Fue una jornada de ciencia viva, donde demostramos una vez más que aprender ciencia es explorar, preguntar, crear y compartir.
```

## Task 6: Integrar `pdf_url` en la renderización del blog

El post `accion-reaccion-rosal` ahora tiene `pdf_url`. El HTML embebido del botón de Drive se eliminó del `content` al migrar a Markdown. Hay que hacer que `blog.js` genere ese botón dinámicamente cuando un post tiene `pdf_url`.

Identificar el bloque del template string donde se construye cada `<article>`. Localizar el cierre del `<div>` de la parte derecha de la tarjeta (el div con título, categoría, summary y fecha).

- [ ] **Step 2: Agregar la función `driveToDownload` en `blog.js`**

Al principio de `blog.js`, después del bloque de comentarios del encabezado, agregar:

```js
// Transforma URL de Drive de visor a descarga directa de PDF
function driveToDownload(url) {
  if (!url) return null;
  if (url.includes('/export')) return url;
  return url.replace(/\/view.*$/, '/export?format=pdf');
}
```

## Pasos manuales post-merge (fuera del scope del código)

Los siguientes pasos requieren acceso al dashboard de Netlify y no se pueden automatizar:

1. En Netlify → **Site configuration → Identity → Enable Identity**
2. En **Identity → Registration** → seleccionar **Invite only**
3. En **Identity → External providers** → agregar **GitHub**
4. Invitar a cada editor por correo desde el dashboard de Netlify

Una vez configurado, los editores pueden acceder a `https://phymac.com/admin`.
